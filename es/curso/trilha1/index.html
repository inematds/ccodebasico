🟢 Qué es

O Claude Code es el agente de codificación de Anthropic que se ejecuta en tu terminal. No es autocompletado ni chat: lee tu proyecto, planifica, edita archivos, ejecuta comandos y pruebas, usa git y navega por la web — siempre pidiendo tu aprobación. Tú hablas en portugués; él ejecuta.

💡 Por qué aprender

A diferencia de pegar código desde un chat, Claude Code trabaja dentro del repositorio real — entiende todo el contexto mediante CLAUDE.md, respeta tu stack y funciona en cualquier sistema. Es la base de todo lo que viene en las próximas rutas.

🔑 Dónde puedes usarlo

DóndeIdeal paraDetalle
Terminal (CLI)Velocidad + controlmacOS, Windows, Linux. La forma principal
VS Code / JetBrainsVer los diffs en el IDEExtensión oficial, el mismo motor del CLI
Web / DesktopDelegar y ejecutar en paraleloclaude.ai/code y app de escritorio (Mac/Windows)

El ciclo del agente: lee → planifica → edita → ejecuta/prueba → muestra el diff → tú apruebas. Entender este ciclo es lo que distingue a quien «juega» de quien produce.

🟢 Qué es

Instalación vía npm. Requisitos previos: Node.js 18+ y, en Windows, Git Bash. El inicio de sesión es por suscripción (Pro/Max mediante el navegador) o por API key de Anthropic.

💡 Por qué aprender

Una versión desactualizada de Node causa fallas silenciosas. En Windows, Claude Code no funciona sin Git Bash: es el error n.º 1 de quienes empiezan. Seguir el orden correcto evita el 90% de los problemas de instalación.

🔑 Paso a paso (orden correcto)

🟩 Windows
# 1. Instale o Git (inclui o Git Bash) → git-scm.com/download/win
# 2. Instale o Node.js LTS → nodejs.org
# 3. Confira:
node -v
npm -v
# 4. Instale o Claude Code:
npm install -g @anthropic-ai/claude-code
# 5. Rode:
claude

Si ocurre un error de Git Bash: setx CLAUDE_CODE_GIT_BASH_PATH "C:\Program Files\Git\bin\bash.exe" y vuelve a abrir la terminal.

🍎 macOS
brew install node
npm install -g @anthropic-ai/claude-code
claude
🐧 Linux / WSL
sudo apt update && sudo apt install -y nodejs npm
npm install -g @anthropic-ai/claude-code
claude
Inicio de sesión (primera vez)
# Dentro do claude, rode:
/login        # abre o navegador → conta Pro/Max (recomendado)

# OU, via API key (pague por uso):
setx ANTHROPIC_API_KEY "sk-ant-..."   # Windows
export ANTHROPIC_API_KEY="sk-ant-..." # macOS/Linux

💡 Consejo: ¿tienes una suscripción Claude Pro o Max? Usa /login con OAuth — sin necesitar una API key, y el uso ya está incluido en tu plan.

🟢 Qué es

Tú ejecutas claude dentro de la carpeta del proyecto y escribe la solicitud en lenguaje natural. Propone ediciones como diffs que apruebas o rechazas. @ hace referencia a archivos y # guarda algo en la memoria.

💡 Por qué aprender

El miedo a que «desordene mi código» desaparece cuando entiendes el ciclo de aprobación: nada cambia sin que veas el diff. Esc interrumpe de inmediato si toma un rumbo equivocado.

🔑 Conceptos clave

cd meu-projeto
claude                          # abre o modo interativo
claude "corrija o bug do login" # pedido direto
claude -p "resuma o README"     # print mode: responde e sai (scripts)
@src/app.py— hace referencia a un archivo
# sempre use pnpm— guarda en la memoria
Esc— interrumpe al agente
Shift+Tab— cambia el modo de permisos

🟢 Qué es

Comandos que empiezan con / controlan la sesión (no el proyecto). Escribe / y mira la lista. Los más usados administran el contexto — el recurso más escaso de una sesión.

💡 Por qué aprender

/clear e /compact son lo que mantiene la sesión rápida y económica. Sin ellos, el contexto se llena, Claude se vuelve lento y «olvida» el comienzo. (La ruta 3 profundiza en esto.)

🔑 Los esenciales

ComandoQué hace
/helpLista todos los comandos
/clearBorra el contexto — empieza una tarea nueva desde cero
/compactResume la conversación para liberar contexto sin perder el hilo
/contextMuestra cuánto del contexto se está usando
/costGasto/uso de la sesión actual
/modelCambia el modelo (Opus / Sonnet / opusplan)
/resumeRetoma una sesión anterior
/initGenera el CLAUDE.md del proyecto (módulo 1.6)
/agentsCrea y gestiona subagentes (recorrido 6)

🟢 Qué es

Presionando Shift+Tab tú alternas entre los modos de la sesión. En modo de planificación (plan mode), Claude investiga y propone un plan — pero no edita nada hasta que tú lo apruebes.

💡 Por qué aprender

En tareas grandes o arriesgadas, dejar que "se ponga a editar" es una receta para tener que rehacer el trabajo. Planificar primero ayuda a definir el camino. El preset opusplan usa Opus (más potente) para planificar y Sonnet (más económico/rápido) para ejecutar: calidad donde importa, ahorro en el resto.

🔑 Los 3 modos (Shift+Tab los recorre)

⌨️ Normal

Pide aprobación en cada edición/comando

⚡ Aceptar automáticamente

Aplica ediciones sin preguntar (acceptEdits)

🗺️ Plan

Solo investiga y propone — no edita

/model opusplan   # Opus planeja, Sonnet executa

🟢 Qué es

O CLAUDE.md es un archivo en la raíz del proyecto con el contexto permanente: cómo ejecutarlo, convenciones, reglas, qué no hacer. El comando /init genera uno para ti analizando el repo. La carpeta .claude/ guarda ajustes, comandos, agentes y skills.

💡 Por qué aprender

Sin CLAUDE.md, Claude empieza desde cero en cada sesión y repite los mismos errores. Con él, respeta tu stack y estilo desde el primer prompt. Es la inversión de 5 minutos que mejora todas las sesiones siguientes.

🔑 Jerarquía de la memoria

1

~/.claude/CLAUDE.md — reglas tuyas, se aplican en todos los proyectos

2

./CLAUDE.md — reglas del proyecto (se suben al git, las usa todo el equipo)

3

./CLAUDE.local.md — solo tuyas, sin versionar

# Projeto X
- Stack: Next.js + TypeScript + pnpm
- Rodar: `pnpm dev` · Testar: `pnpm test`
- Convenção: componentes em PascalCase, sem default export
- NUNCA commitar direto na main

Atajo: escribe # sua regra en la sesión para adjuntar algo al CLAUDE.md en el momento.

🟢 Qué es

De forma predeterminada, Claude pide permiso antes de editar archivos o ejecutar comandos. Tú defines listas de allow / deny e o modo de permiso. El comando /permissions administra todo.

💡 Por qué aprender

El permiso es tu cinturón de seguridad. Permite comandos seguros (p. ej.: npm test) reduce los clics; pero nunca usa bypass en máquinas con datos sensibles o en producción.

🔑 Modos de permisos

ModoComportamientoRiesgo
predeterminadoPide en cada acción sensibleBajo
acceptEditsAcepta ediciones automáticas de archivosIntermedio
planSolo planifica, no cambies nadaNinguno
bypassPermissionsNo pide nada (--dangerously-skip-permissions)Alto ⚠️
/permissions          # abre o gerenciador
# em .claude/settings.json:
# "permissions": { "allow": ["Bash(npm test)"], "deny": ["Bash(rm -rf *)"] }

⚠️ No hagas: ejecutar --dangerously-skip-permissions en tu máquina personal solo para "ir más rápido". Usa esto únicamente en contenedores/VMs descartables.

🟢 Qué es

Tú usas Claude Code mediante suscripción (Pro/Max — uso incluido) o por API (paga por token). /cost muestra el gasto de la sesión. La elección del modelo es lo que más influye en el costo y la velocidad.

💡 Por qué aprender

Usar Opus para todo es caro e innecesario. Sonnet resuelve el día a día; Opus, lo difícil; opusplan combina los dos. Junto con /compact e /clear, tú controlas el gasto.

🔑 Modelos: cuándo usar cada uno

ModeloUsa para
OpusTareas difíciles, arquitectura, debugging complicado
SonnetEl día a día: rápido y capaz, con la mejor relación costo-beneficio
HaikuTareas simples y económicas, alto volumen
opus[1m]Contexto de 1 millón de tokens (repos enormes)
/cost                       # gasto da sessão
/model sonnet               # troca pro Sonnet
claude --model "opus[1m]"   # abre com contexto de 1M

💡 Consejo para ahorrar: empieza la tarea con /clear, usa opusplan y ejecuta /compact cuando el /context superar ~70%.
